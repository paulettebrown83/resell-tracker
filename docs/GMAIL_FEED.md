# Gmail notification intake

This is a private Vinted notification reader, not a marketplace publisher or a canonical sale importer. Code and local tests do not mean consent, runtime deployment or the schedule is active. Record the actual deployment and hosted acceptance separately. The production Shop activity screens were visually checked in Comet before this addition; the new Gmail connection still needs its own hosted check.

## Paulette's workflow

Open **Shop activity → Connect or check Gmail**. The page shows the enrolled account, status, last fully checked window and a bounded error name. Choose **Connect Gmail** for the recorded Vinted account. Enrollment uses the current member's bearer and an account/member-scoped stable request ID. Google consent is separate from the existing Google sign-in. The reader requests only `https://www.googleapis.com/auth/gmail.readonly`; that permission can read mailbox content broadly. Sender and date filtering are application restrictions, not Google-enforced sender-only access.

An uncertain enrollment retries the same ID in that browser tab. A failed/expired OAuth attempt starts a new one-use flow. **Pause background checks** fences active leases in the database; it does not delete stored evidence or revoke the Google grant. Reconnect requires explicit consent again. Google Account connections can revoke the grant. Saved source facts remain available for review.

## Runtime boundaries

`app/api/integrations/gmail/start` accepts a same-production-origin POST and member bearer. It creates a 32-byte HttpOnly/Secure/SameSite=Lax cookie restricted to the callback path. It forwards only the feed ID, cookie binding and bearer to `resale-gmail-sync`. The Edge Function verifies the actual Auth user; its service-only OAuth RPC checks live member ownership. State and cookie are stored as SHA-256 hashes; the private state holds a random PKCE verifier and expires in 600 seconds.

Exact callback: `https://resell-tracker-beta.vercel.app/api/integrations/gmail/callback`. The server forwards the code, state and cookie binding; SQL consumes state once before code exchange and rechecks membership. Edge exchanges the code, verifies exact readonly scope and `users.getProfile(me)` mailbox, then calls the narrow completion RPC. Tokens never enter responses, browser variables, source records or logs. Callback immediately redirects to a clean settings URL and clears the cookie. No application logging captures query parameters; hosting providers may retain their own request metadata under their configured policies.

The Supabase Edge Function uses its built-in server environment (`SUPABASE_SECRET_KEYS.default`, legacy service-role fallback; corresponding publishable/anon key) for narrowly named RPC calls. These keys remain solely in that managed runtime. Mixed endpoint `verify_jwt=false` is intentional: start verifies a real Auth bearer, callback verifies single-use state/cookie/PKCE, and tick verifies a dedicated HMAC before issuing a lease. No CORS grant or generic Vault reader/writer is exposed.

The standalone scheduled Worker `workers/resale-gmail-tick/worker.mjs` contains no Google tokens, Cloudflare management token or Supabase service key. It receives only `GMAIL_TICK_SIGNING_KEY` plus public `GMAIL_EDGE_URL`. Every five minutes it signs exact UTF-8 `gmail_tick_v1\n` + JSON `{v:1,nonce,expires_at}`. The private SQL routine verifies signature, expiry/replay, current ownership, active feed and a fenced lease. HTTP invocation of the Worker returns404; only its scheduled handler runs intake. Deploy its single module without a bundler.

## Bounded, deterministic parsing and progress

Edge fetches Google access tokens in memory from the Vault-held refresh token and verifies the mailbox profile each run. It reads at most one page of25 messages per run, one message at a time, with8-second per-request timeouts and a45-second message-loop budget. The first window covers the previous7 days ending60 seconds before now. Later completed windows overlap by300 seconds. Before reading a page, its at-most25 message IDs and next-page token are checkpointed. Each confirmed ingestion removes only that ID and checkpoints the remaining list. A time-budget exit resumes the saved list rather than refetching an ever-repeated prefix. Failed ingestion retains its exact pending ID; message dedupe prevents a second source. An invalid page token restarts the same window. Only finishing every page marks the window complete. This is query-window coverage, not proof that Gmail cannot later index or import older mail; gaps outside the overlap require a reviewed backfill.

Parser `vinted-gmail-v1` checks the observed sender, Gmail authentication-results header, exact account greeting, subject and actual body structure. A sale notice preserves item title, message/conversation identity and unallocated money. A shipping-label notice preserves its explicit transaction ID as evidence, never as a fabricated order/listing ID. Buyer names, addresses, tracking codes, attachments and raw bodies are not copied into normalized records. Body links are decoded only for an exact Vinted inbox path; no links or image URLs are fetched. Unknown/unsupported/authentication-mismatched messages are quarantined, with a reason. No cancellation template is claimed as recognized yet.

The checksum covers `JSON.stringify({id,threadId,internalDate,payload})` in that property order, using the Gmail full-message representation. Mutable label/history fields are excluded. Received time is Gmail `internalDate`, not sale time. A separate Vault ingress key signs exact UTF-8 `gmail_ingest_v1\n` + receipt. The data contract checks member/feed/account/parser/lease/nonce and produces one immutable source plus one blocked source-review operation. Existing exact Gmail sources are reused only with a linked review of newly parsed facts; old normalized values are preserved. No stock, sale, order, matching or remote-listing effect occurs.

`invalid_grant`, access denial, unexpected scope/mailbox, or unexpected refresh-token replacement pauses for reconnect. A replacement token is not silently discarded while polling continues; the feed stops and explicit OAuth reconnect persists a fresh token through the reviewed Vault path. Network/rate errors retain the incomplete cursor. Permanently missing or unreadable messages pause the feed with the pending ID intact. Reconnect does not clear that gap. A coordinator must inspect the exact Gmail message, record an explicit missing-source review/gap and decide a bounded backfill or recovery before resuming; there is no automatic skip route. Raw provider errors and secret material never enter status fields.

## Deployment checklist and nonsecret configuration

1. Apply only the independently reviewed Gmail feed migration; record its exact SHA and hosted ledger version. Do not replay older migrations. The server RPC contract and coordinator metadata live with that migration.
2. Configure `private.resale_gmail_config`: the dedicated Google client ID, exact callback and actual `unknown|testing|production` publishing state. Testing/unknown stores authorized credentials but keeps the feed paused; do not promise unattended durability on Google's seven-day Testing refresh token.
3. Store distinct Vault names under `resale_gmail_paulettebrown83_production_`: `oauth_client_secret`, `oauth_refresh_token`, `tick_signing_key`, `ingress_signing_key`. Signing keys are independent32-byte hex strings. Only the tick key is copied to the Cloudflare encrypted binding. Google secrets stay in Vault, consumed by Edge RPCs; no runtime Google-secret duplication is needed.
4. Deploy Edge entrypoint `supabase/functions/resale-gmail-sync/index.mjs` with relative modules and custom-auth `verify_jwt=false`. No third-party runtime dependencies. Verify signed-out start, wrong cookie/state, invalid tick and method denials before consent. Built-in server keys are never added to Vercel or Cloudflare.
5. Deploy the reviewed tracker routes and public privacy/terms pages. Existing public Supabase URL/key suffice in Vercel; no new Vercel secret is needed. Preview start/callback activation is denied and browser writes remain blocked.
6. Complete consent for the enrolled owner and mailbox. Verify actual token scope/profile, stored Vault metadata and publishing state without printing values. Exercise one controlled signed tick before enabling the schedule. Verify real message replay dedupe, unknown quarantine, lease/replay denial and unchanged inventory/sales. Then deploy the scheduled Worker with the exact Edge URL and tick key.

Local tests: `npm run test:gmail-runtime`, full `npm test`, typecheck, lint, build and audit. Two prior real Vinted MIME messages were replayed privately to verify parser body structure; sanitized synthetic fixtures cover adversarial cases in Git. These are not a substitute for a live Gmail OAuth/REST/Edge acceptance run. Private source files and checksum reports remain outside the public repository. Clean owned temporary builds, dependency symlinks, processes and browser pages after acceptance; preserve final source and evidence.
